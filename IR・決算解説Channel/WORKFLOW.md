# 動画を作る手順と注意点

1本作るたびにこのファイルを見ながら進める。作業中に気づいたことは、最後の「更新履歴」に書き足し、該当する手順も直す。

## 守ること（毎回）

- **株価に関わる数字を扱わない。** 株価、時価総額、PER、PBR、配当利回り、目標株価は出さない。
- **株価の動きを分析しない。** 「この決算で株価が上がった・下がった」の話はしない。売買の推奨もしない。
- **配当も扱わない。**
- **IR 資料から読み取れることと、今後の戦略の解説に絞る。**
- **売上と利益を同じ重さで扱う。** 事業別・地域別の売上を見せる画面には、必ず事業利益（会社の本業の利益。日本基準の会社は営業利益）の額と利益率を併記する。「どこが伸びたか」と同じくらい、「どこが利益を残しているか（利益率が高いか）」を解説する。
- **事実と会社の説明を分ける。** 数字は事実として言う。理由や見通しは「会社は〜と説明しています」の形で言う。自分の推測を入れるときは「〜と考えられます」と明示する。
- **数字は一次資料から取る。** ニュース記事やまとめサイトの数字は使わない。
- **スライドは、作る前に必ずその会社の規約を確認する**（手順2）。

## 手順

### 1. 会社と決算を決める

- Phase 1 は通期決算だけ。
- 会社の IR ニュース一覧で、通期決算の公表日と資料をそろえる。
- `episodes/epNN_<会社>_<決算期>/` を作る。

### 2. 規約を確認する（必須）

1. 会社のサイトのフッターから、次のページを探して読む。
   - 免責事項
   - サイトのご利用条件（利用規約）
   - 著作権
   - リンクポリシー
2. 著作物の使用について書かれた文を、そのまま `PLAN.md` の「規約の確認」に写す。確認した日と URL も書く。
3. 判定する。

| 規約の書き方 | 判定 |
|---|---|
| 著作物の使用について書いていない | スライドを使う |
| 「著作権法で認められた範囲を超えて許諾なく使えない」のように、法律の範囲内の利用を認めている | スライドを使う |
| 引用・転載・動画での使用をはっきり禁止している | スライドは使わず、数字から自分で図を作る |
| 写真などを自由に使ってよいと書いている（フォトライブラリーなど） | その画像は使ってよい。対象の範囲を `PLAN.md` に書く |

- スライドを使う場合も、引用の形を守る（下の「スライドの見せ方」）。
- 企業ロゴは使わない。社名は文字で書く。

### 3. 資料を集める

| 優先 | 資料 | 取るもの |
|---|---|---|
| 1 | 決算短信 | 損益計算書、セグメント情報、販管費の内訳 |
| 2 | 決算説明会資料、決算サマリー | 増減の理由、地域別の数字、来期の見通し |
| 3 | 有価証券報告書 | 事業の内容、リスク、従業員数、平均年収、平均勤続年数 |
| 4 | 経営者のプレゼン、統合報告書、中期経営計画 | 戦略 |

- 有価証券報告書は決算発表から1〜3か月遅れて出る。出ていなければ `PLAN.md` にそう書き、出たら追加する。
- 資料の URL と公表日を `PLAN.md` の「使った資料」に書く。

### 4. 数字を入れて検算する

- 決算短信の数字（百万円）を `data.json` に書く。表示は会社の資料に合わせて億未満を切り捨てる。
- 次の検算を必ずする。
  - 売上収益 − 売上原価 ＝ 売上総利益
  - 売上総利益 − 販管費 ＝ 営業利益（IFRS の会社は、会社が使う指標。ファーストリテイリングは「事業利益」）
  - セグメントの売上の合計 ＝ 連結の売上（「その他」「調整額」も含める）
  - 流れ図の各段で、入る帯の合計と出る帯の合計が同じ
- 日本基準と IFRS で項目が違う。日本基準は「営業外収益・費用」「経常利益」「特別損益」がある。IFRS は「その他の収益・費用」「金融収益・費用」で、経常利益がない。

### 5. 分析して骨子を作る

- 伝えるポイントを5つ以内に絞る。
  - 何で稼いだか
  - どこが伸びたか
  - どの事業・地域の利益率が高いか（売上の伸びと同じ重さで扱う）
  - 利益率はなぜ変わったか
  - 弱いところ
  - 来期の見通しと戦略
- 3つの対象（ビジネスマン、転職・就活、個人投資家）すべてに向けて、それぞれの見どころを1つずつ入れる。
- 骨子は `PLAN.md` に書く。長さは10〜12分を目安にする。

### 5.5 戦略パートを厚くする

戦略パートは動画の中心の1つ。決算の数字の解説より優先する。

1. 会社の戦略を、まず全体像（柱が何本あるか）で見せ、そのあと柱ごと、施策ごとに1つずつ解説する。
2. 施策ごとに、必ず画面を1つ用意する。次の順で選ぶ。
   - スライドを使える会社（手順2で判定）：その施策のスライドを引用する。
   - スライドを使えない会社：説明会のスクリプトや資料の文から、図を作って構造化する（`pillars`＝柱の図、`flow`＝流れ図、`kpi`＝大きな数字の推移）。
   - 写真：会社のフォトライブラリーなどの利用条件を確認し、商業目的でも使えるものだけ使う。報道・非営利目的に限る素材（例：トヨタの画像・動画ダウンロード）は使わない。
3. 図には「会社の説明から当チャンネルが整理」と小さく書き、会社の資料そのものではないことを示す。
4. 決算説明会のスクリプト（話す原稿）や社長のスピーチを読み、戦略の「理由」（なぜその施策をするのか）と「目指す姿」（数字の目標）を必ず入れる。
5. 長さが足りないときや戦略を厚くするときに削るのは、優先度の低いものから：補足的な事業・地域の詳しい数字 → 課題とリスクの個別の説明 → 販売台数などの補足。売上・利益・利益率と来期予想は削らない。
6. 戦略の資料にも、時価総額・PBR・自己株式の取得・配当がよく出てくる。株価や株主還元の話なので、戦略パートでも使わない（例：三菱UFJの「時価総額でグローバルトップ5」は「世界を代表する総合サービスグループへ」と言い換えた）。
7. 説明会のスクリプトがない会社（資料が有価証券報告書だけの会社）は、有価証券報告書の「経営方針、経営環境及び対処すべき課題等」に説明会の内容がまとまっていることが多い。そこから柱と施策を取る（#6 ソニー）。
8. 社長・CFO の名前や地名は、戦略パートで初めて出ることが多い。必ず `readings` に入れて kana を確かめる。
9. 戦略パートの目安は3〜4分、章は「全体像」＋施策ごとに4〜5章。動画全体は10〜12分に収める。

### 6. 図とサムネを作る

```bash
python scripts/sankey.py episodes/<id>/data.json episodes/<id>/sankey.png
python scripts/sankey.py episodes/<id>/data.json episodes/<id>/thumbnail.png --thumb
```

- 流れ図は、説明したい部分を1か所だけ強調する（`thumbnail.highlight`）。
- サムネの一言は、図の強調部分と同じことを言う。入れる数字は資料で確かめられるものにする。
- 他の書籍・サービスのデザインやキャラクターを流用しない。

### 7. スライドの見せ方

- 枚数は決めない。ただし1枚ごとに必ず自分の解説を付け、解説が主になるようにする。「今後の戦略」のように会社の説明そのものが中身になるパートは、スライドを多めに使ってよい（#1 は12枚）。
- 枠で囲み、自作の図と区別する。
- 画面下に「出典：〇〇株式会社『資料名』（公表日）」を出す。
- 文字や数字を書き換えない。強調の印は上に重ねる。
- 映している間は、そのスライドを自分の言葉で読み解く。読み上げるだけにしない。

### 8. 台本を書く

- 冒頭30秒で一番強い事実を言う（例：「増えた売上の約9割が海外」）。
- 専門用語は初めて出たときに一言で説明する。
- 数字と固有名詞の読みを、音声エンジンの読み（`audio_query` の kana）で確かめる。下の「読み間違いの一覧」に載っている語は特に見る。
- 動画の最後に注意書きを入れる：「この動画は IR 資料をもとにした解説で、投資を勧めるものではありません」。注意書きは最後の1回だけにし、冒頭で繰り返さない。
- 同じことを2回言わない。冒頭で言ったことを、すぐ後でもう一度言わない。
- 対象外の話題を入れない。配当は株価や投資判断に近い話題なので、Phase 1 では扱わない。

### 9. 動画を作る

1. 資料の PDF を `episodes/<id>/sources/` に置く（Git には入れない）。
2. 台本と画面を `episodes/<id>/spec.json` に書く。
   - `scenes`：章（`chapter`）ごとにセリフ（`lines`）を並べる。章がそのまま YouTube のチャプターになる。
   - セリフの `t` が字幕と読み上げの文。画面は `v` で指定し、次に `v` が出るまで同じ画面を出す。
   - 画面の種類：`title`（大きな文字）、`points`（箇条書き）、`sankey`（流れ図。`upto` で途中の列まで、`highlight` で強調）、`bars`（棒グラフ。`sub` に「事業利益 ○億円（利益率 ○%）」を書くと棒の下に出る）、`table`（表）、`cards`（カード）、`slide`（スライドの引用。PDF とページを指定）、`pillars`（戦略の柱。列ごとに見出しと中身。`hl` で強調する列、`hl_items` で強調する項目）、`flow`（矢印でつないだ流れ。`steps` に見出しと説明）、`kpi`（大きな数字の推移）。
   - 読みを変えたい語は `readings` に書く（例：`"IR": "アイアール"`）。
3. VOICEVOX を起動して動画を作る。

```bash
~/voicevox/macos-arm64/run --host 127.0.0.1 --port 50021
python scripts/make_video.py episodes/<id>/spec.json
```

4. `build/` にできたものを確認する。
   - `video.mp4`：動画
   - `thumbnail.png`：サムネ
   - `chapters.txt`：チャプター
   - `kana.txt`：全セリフの読み。数字と固有名詞の読みを確認する
   - `frames/`：全画面。重なりや切れがないか確認する

- 声は当面 VOICEVOX の「No.7 アナウンス」（速さ 1.1）。参考動画のような声（ElevenLabs など）に変えるかは検証中。
- 説明会資料の PDF は「スライド＋話す原稿」の縦長ページなので、`slide` はスライドの外枠で自動的に切り出す。外枠のない資料は切り出しを確認する。

### 10. 公開前の確認

- [ ] 画面と台本の数字が、決算短信と一致している
- [ ] 株価に関わる数字や、株価の動きの話が入っていない
- [ ] 引用したスライドに出典が出ている
- [ ] 規約の確認結果が `PLAN.md` にある
- [ ] 概要欄に、使った資料の名前と URL、AI 利用の表示、注意書きがある

### 11. アップロード

- 非公開でアップロードし、公開はチャンネル所有者が YouTube Studio で行う。
- アップロード先は囲碁チャンネル（@IGO-Channel-JP）と同じ。認証ファイル（`credentials.json`、`token.json`）のあるフォルダを `--auth-dir` で指定する。

```bash
"/Users/yibozhou/Desktop/Claude開発APP/youtube-pdca/venv/bin/python" scripts/upload.py episodes/<id>/spec.json --auth-dir .auth
```

- 標準の `python3` には Google のライブラリが入っていない（`No module named 'google.auth'` になる）。上の venv の python を使う。
- 動画づくり（`make_video.py`）は標準の `python3` でよい。引数は `spec.json` のパス（フォルダではない）。

## タイトルのひな形

`【決算解説】<通称>（<補足>）<今回の発見>｜<決算期>`

例：
- `【決算解説】ユニクロ（ファーストリテイリング）増えた売上の9割は海外、利益率も国内超え｜2026年8月期`（#1、チャンネル所有者が選んだ形）
- `【決算解説】GO（タクシーアプリ）営業利益2.6倍、主力事業の利益率は39%｜2026年5月期`
- `【決算解説】キオクシア 営業利益ほぼ2倍、AI需要で利益率37%｜2026年3月期`

- 先頭の【決算解説】でシリーズをそろえる。続けて、一番検索される呼び方を置く。
- （）には正式社名か、何の会社か分かる補足を入れる。通称と正式社名がほぼ同じなら省く。
- 「今回の発見」は、資料で確かめられる数字を1つか2つ入れる。売上だけでなく利益・利益率の数字を入れる。誇張や「株価」「買い」などの言葉は入れない。
- 全体で50文字前後にする（上限は100文字）。

## 概要欄のひな形

```
<会社名>の<決算期>の決算を、IR資料から読み解きます。

━━━━━━━━━━━━━━━━
⏰ チャプター
{chapters}
━━━━━━━━━━━━━━━━

▼出典（<会社名> IRサイト、<公表日>公表）
・<資料名>（引用：p.○）
　<URL>
引用したスライドの著作権は<会社名>に帰属します。流れ図・グラフ・表は、資料の数字から当チャンネルが作成しています。

この動画はIR資料をもとにした解説で、投資を勧めるものではありません。
この動画はAIを使って制作しています（台本の作成支援・図の自動作成・音声合成）。
```

## 画面づくりの注意

- カードが3枚以下のときは、横いっぱいの段を縦に並べる。2列にすると空白が残って不自然になる。
- 事業別・地域別の売上の棒グラフには、`sub` で事業利益と利益率を併記する。利益率どうしを比べる棒グラフ（前期と今期）も別に作る。
- 決算短信のセグメント情報に事業利益（または営業利益）がない地域・事業は、決算説明会資料の表から取る。前期の利益率が載っていないときは、今期の率と前期差から計算し、画面にそう書く。
- 単一セグメントで、用途別・地域別の利益が開示されていない会社は、そのことを動画で言い、会社全体の利益率と四半期ごとの利益率の推移で利益の動きを見せる（#3 キオクシア）。
- 売上が小さい会社（数百億円規模）は、`data.json` に `"decimals": 1` を入れて億円を小数1桁まで出す。丸め方は会社の資料に合わせて `"rounding": "floor"`（切り捨て）か `"round"`（四捨五入）にする。

## 会社ごとの事情への対応

| 事情 | 対応 | 例 |
|---|---|---|
| 上場して間もなく、通期の決算短信・決算説明資料がない | 有価証券報告書と「事業計画及び成長可能性に関する事項」から数字と戦略を取る。来期予想は、その後の四半期決算短信に載っている通期予想を使い、出典に書く | #2 GO |
| 1年分の業績予想を出さない | 決算発表時点の次の四半期ガイダンスと、会社の市場見通しを紹介し、「1年分の予想は出していない」と言う | #3 キオクシア |
| 規約でコンテンツのアップロード・頒布を禁止している | スライドは一切使わず、すべて数字から自作の図にする。概要欄の「引用したスライドの著作権は〜」の文は入れない | #3 キオクシア |

- 箇条書きが5項目以上のときは、行の間隔を詰めて画面に収める。
- 表の列見出しは短くする（1列は画面幅の2割ほどしかない）。長い期の名前は表の題に書き、見出しは「第4四半期 実績」のようにする。
- 流れ図の左の項目名と、棒グラフの項目名は10文字程度までにする。長いと画面の左端で切れる。正式名は注記に書く（例：「テレビ・カメラなど＝エンタテインメント・テクノロジー＆サービス」）。
- `kpi`（大きな数字）の値は6文字程度までにする。文字が大きいので、長いと隣の項目にはみ出す（例：「MUFG UNITY」ではなく「新サービス」と書き、名前は説明文に入れる）。
- `kpi` の値は、漢字や「最大」を含むと6文字でも幅が足りない（例：「最大50倍」「750万人」は矢印に重なった）。値は「50倍」「1/35」「750万」のように短くし、「最大」「人」は説明文に回す。
- `kpi` の4桁の数字に「億」「万」を付けると矢印に重なる（例：「2440億」「1500万」）。値は「2440」「1500」にし、「億ドル」「万人」は説明文の頭に回す。
- サムネの見出しは1行7文字程度まで。「売上18%のAWSが」（9文字）は右の図に重なった。
- `pillars`（柱の図）を4列にするときは、各列の項目を1つにする。2つ以上だと文字が入らない。
- `flow`（流れ図）は4段まで。5段以上は2枚に分ける。
- 流れ図で小さい項目が隣り合うと、ラベルが重なる。`data.json` の `gap` を広げるか、項目の並び順を変えるか、小さい項目どうしをまとめる（例：法人所得税と非支配持分）。動画を作る前に、全体の流れ図を1枚描いて確認する。
